## Mode Selection Contract

### Agent Runtime source repository

Source mode requires all three source markers:

1. root `pyproject.toml`;
2. `src/agent_runtime/config.py`;
3. the packaged template continuity gate.

Source mode preserves the existing strict sequence and content contract:

```text
README bilingual entry and Runtime pointers
-> NEXT-SESSION-POINTER schema and required fields
-> AGENTS/CLAUDE continuity and self-improvement rules
```

It does not require a consumer config or lock.

### Generated consumer

A non-source checkout can activate consumer behavior only when all of the
following are true:

1. `agent_runtime.yml` parses through the packaged bounded loader and declares
   `agent-runtime-config/v2`;
2. `agent_runtime.lock.json` is valid JSON and declares
   `agent-runtime-lock/v2`;
3. config and lock agree exactly on project and every upstream field;
4. every lock ownership entry is a safe repository-relative path, uses a
   supported mode, and equals the config's effective ownership;
5. lock ownership explicitly covers `AGENTS.md`, `CLAUDE.md`, and
   `agents/project/NEXT-SESSION-POINTER.yml`;
6. both `AGENT_RUNTIME.md` and the continuity gate are `managed` in config and
   lock, carry canonical SHA-256 entries, exist, and match those digests.

Any failure records a stable finding and falls back to the strict document
checks. There is no generic “consumer checkout” skip.

## Ownership Decision Matrix

| Surface | Lock/config result | Enforcement |
| --- | --- | --- |
| `README.md` absent from selected lock ownership | Runtime does not own or select it | preserve host README; do not impose Runtime wording |
| `README.md` selected as `managed` or `seed_once` | ownership is proven and non-host | retain strict bilingual/pointer checks |
| `AGENTS.md` / `CLAUDE.md` as `host_owned` | config and lock must agree | preserve and exclude only that document from Runtime wording checks |
| `AGENTS.md` / `CLAUDE.md` as `seed_once`, `managed`, or unproven | not host-exempt | retain strict protocol rule validation |
| `AGENT_RUNTIME.md` | must be managed and digest-matched | validate the complete common Runtime rule set independently |
| `NEXT-SESSION-POINTER.yml` | any mode | always validate existence, v1 schema, and required fields |

The managed Runtime contract is checked separately from non-host protocol
documents. Consequently, a valid `AGENT_RUNTIME.md` cannot mask an invalid
seed-once `AGENTS.md` or `CLAUDE.md`.
