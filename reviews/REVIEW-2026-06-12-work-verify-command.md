# Work Verify Command Closeout

## Bottom Line

`UNIT-TASK-AR-372-005` adds deterministic verification execution to the Work
CLI: `python scripts/work.py verify <id>` now runs declared verification
commands and writes evidence under `reviews/`.

| Check | Result | Evidence |
| --- | --- | --- |
| Passing command execution | pass | `tests/test_work_verify.py` |
| Failing command evidence | pass | failed commands return nonzero and write failed evidence |
| Missing command guard | pass | missing verification commands fail before evidence creation |
| Frontmatter update | pass | `verification_status`, `verified_at`, `verified_by`, `evidence_refs` |
| Evidence index | pass | `reviews/INDEX.md` regenerated by work verify |

## Insight

- This turns verification from a handwritten closeout note into a deterministic
  command result.
- The command still respects planner-authored criteria; it does not invent or
  approve missing checks.
- `work close` should build on this by requiring passed verification evidence
  before marking work done.

## Decision

- Decision: `work verify` executes only declared frontmatter verification
  commands.
- Decision: failed verification still writes evidence, because failed evidence
  is useful for debugging and routing.
- Decision: keep `work close`, actuals, costs, and resolution semantics as the
  next separate slice.
