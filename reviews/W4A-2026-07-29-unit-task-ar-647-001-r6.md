## W4b Finding 1 — Selected Profile With Missing Gate

The former dispatcher treated a missing
`scripts/security_service_gate.py` as proof that the host was core-only. That
inference was invalid for a selected profile whose install was incomplete or
damaged.

The missing-gate seam now determines whether security-service is expected from
bounded, stable, non-symlink state:

- `agent_runtime.yml` or legacy `ralph.yml`;
- `agent_runtime.lock.json`;
- `.allimbot.json`;
- `agents/project/SECURITY-SERVICE-POLICY.json`;
- `docs/security-service.md`; and
- `scripts/allimbot.py`.

The config reader recognizes the documented v2 profile list, treats legacy v1
as full-runtime, validates supported profile identifiers, and handles
`full-runtime` as security-service selected. The lock reader requires the v2
schema and a supported profile list. Malformed, unreadable, oversized,
symlinked, or concurrently changed profile state refuses claim creation.

Both missing-parent and missing-final-file paths use this check. A selected or
partially installed profile therefore refuses before claim persistence:

```text
v2 config: [core, security-service]
  returncode=1
  persisted_claims=0

v2 config: [full-runtime]
  returncode=1
  persisted_claims=0

v2 lock: [core, security-service]
  returncode=1
  persisted_claims=0

partial install: .allimbot.json present, gate removed
  returncode=1
  persisted_claims=0
```

Each fixture targets a deficient canonical `.env.production` unit. The
positive isolation fixture writes an explicit `core` v2 config with a legal
inline comment and proves the unchanged zero-burden result.

When the gate is present, the earlier protections remain unchanged: real
parent directory, bounded regular final file, stable descriptor snapshot,
exact managed SHA-256, and execution of the verified source snapshot through
stdin.

## W4b Finding 2 — Fixed Plain-Scalar Registry Subset

The registry parser no longer applies a broad “not obviously dangerous”
character filter to every scalar. Each authorization-relevant scalar now has
an explicit contract:

- `updated_at`: exact timestamp/template syntax plus real ISO calendar and
  timezone validation for concrete values;
- team `display_name`: bounded unquoted plain text from a fixed character
  alphabet;
- role `tier` and `team`: canonical Runtime role identifiers;
- role/team IDs: canonical direct-list-item identifiers; and
- `tiers` and `aliases`: bounded unique inline lists with canonical items.

Quotes, YAML tags, anchors, block scalar markers, container syntax, control
characters, unsupported indentation, nested role-like records, duplicate
fields, and trailing document garbage do not reach optional Allimbot import.

The exact fifth-W4b shape is fixed by an import-sentinel regression:

```text
updated_at: "
...
  - id: discord

result=EventPolicyError(owner_role registry is unavailable or malformed)
optional_import_calls=0
```

The root and template ORG registries both continue to pass, including the
template timestamp placeholder.
