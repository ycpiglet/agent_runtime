## W4b Finding — Physical HTML Block Lines Are Never Reparsed

The former scanner removed `<!-- ... -->` and then tested the remainder of
the same physical line as Markdown. That was incompatible with CommonMark
block semantics:

```text
<!--
hidden
-->## Security Controls
```

The whole closing line belongs to the HTML block. The trailing H2 text is not
rendered and must not authorize a claim.

The replacement scanner carries explicit non-rendered block state:

1. fenced backtick and tilde blocks retain their existing close-marker
   handling;
2. HTML comments continue through `-->`;
3. CDATA continues through `]]>`;
4. processing instructions continue through `?>`;
5. declarations continue through `>`;
6. `script`, `pre`, `style`, and `textarea` blocks continue through their
   case-insensitive closing tags, including across blank lines; and
7. tag-shaped CommonMark blocks continue through the next blank line.

When any terminator appears, the scanner clears the state only for the next
physical line. It always skips the complete terminator line, so text following
`-->`, `</script>`, or another terminator on that line cannot become an H2.

Inline or malformed comment syntax is also ineligible to make a security
heading more trustworthy. The line is skipped, and an unclosed comment keeps
the conservative block state.

The raw-tag start rules include whitespace, `>`, and end-of-line forms, are
case-insensitive for the four raw tags, and accept attributes without
reinterpreting their content.
