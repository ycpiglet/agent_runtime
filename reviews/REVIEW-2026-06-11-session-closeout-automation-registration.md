## Insight

- Root cause: the runtime has strong Owner governance at completion, but it lacks a session baseline that distinguishes pre-existing state, current declared work, and late dirty work generated by another pane or background process.
- Failure mode: without a baseline, closeout work repeatedly devolves into manual stash inspection, archive refs, ad hoc issue comments, and uncertain claims about whether "everything else" is clean.
- Prevention: use a baseline snapshot plus dirty-intake classifier before any archive/drop/branch cleanup action.

## Decision

- Decision: build the prevention layer as a taskset, not as another ad hoc cleanup.
- Decision: keep destructive or external actions explicit. The first implementation must classify and propose; archive push and issue creation require policy or Owner approval.
- Decision: package the operator behavior in a reusable `session-closeout` skill so "마무리/정리" has a stable implementation contract.

## Risks / Blockers

- Risk: automatic archive push could preserve sensitive data if run without classification and policy boundaries.
- Risk: Stop hooks that mutate state can hide root causes; the default path must be read-only unless Owner-approved side effects are enabled.
- Risk: hook changes load only on new sessions, so implementation must include direct script tests and documented restart expectations.
- Blocker: none for registration; implementation should start with read-only baseline and classifier tasks.
