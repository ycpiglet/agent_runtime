## v2 Transaction Contract

The real index is used only to leave failed claim artifacts visibly staged for
recovery. The candidate commit is built separately:

1. resolve a symbolic branch and starting `HEAD`;
2. create a random, mode-`0600` private index below Git's private
   `agent-runtime/claim-commit` directory;
3. load starting `HEAD` with `read-tree`, add only the requested claim JSON,
   handoff, and log, record their exact mode/blob OIDs, and seal `write-tree`;
4. persist a mode-`0600` v2 record binding root, live owner PID, nonce, claim
   paths, all artifact entries, starting `HEAD`, symbolic ref, exact private
   index, and sealed tree;
5. run `pre-commit`, `prepare-commit-msg`, and `commit-msg` with
   `GIT_INDEX_FILE` pointing to the private index;
6. revalidate the entire private tree, every target working blob, the exact
   record bytes, `HEAD`, ref, and non-empty message;
7. call `commit-tree` with the already sealed tree and update the symbolic ref
   using `update-ref <ref> <new> <old>`;
8. remove marker, index, message, and lock files on every exit.

The current test host uses Git `2.34.1`, so W4a exercised the documented older
POSIX direct-hook compatibility path. Git `2.36+` uses `git hook run`.
Configured hooks on older Windows fail this optional SCM path closed.

## Gate and Fail-Closed Boundaries

The canonical gate validates the exact private path without resolving away a
final symlink, file permissions on POSIX, current symbolic ref and `HEAD`,
private-index `write-tree`, every index mode/blob entry, and the complete
`HEAD`-to-sealed-tree delta. The delta must be non-empty and contained wholly
in the marker's artifact set.

Focused regressions reject:

- missing, malformed, ambient, dead-owner, wrong-root, wrong-path,
  wrong-`HEAD`, wrong-ref, wrong-index, wrong-tree, wrong-blob, and wrong-mode
  markers;
- a removed claim, an extra private-index path, or an omitted changed sidecar;
- JSON, handoff, or log mutation/restaging after the real gate returns;
- hook failure, detached `HEAD`, and compare-and-swap ref loss.

Failure does not advance the claim transaction. The private directory is empty
after every tested exit, the real claim artifacts remain staged, and the
ordinary gate reports `task-claim:authorized-commit-not-persisted`.
