## P1 — Final Publication Omits the Real Worktree HEAD Reflog

`scripts/claim_guard.py` publishes via `update-ref` in a private detached
administrative context (`GIT_DIR=<nonce>.git` with a `commondir`) rather than
via the actual worktree context.  The branch reflog is updated, but the real
worktree's `logs/HEAD` is not.  Source: product lines 689–700 perform the
private-context `update-ref`; lines 711–735 only verify current `HEAD` and run
the post-hook, without recording the actual worktree HEAD transition.

### Deterministic independent reproduction

In a disposable normal Git repository, I called the real
`claim_guard.commit_claim_artifacts()` with claim JSON, handoff, and log.  The
transaction returned success:

```text
result={"commit":"65b46863afcdf166e53588add5ddade96366bed4",
"committed":true,"ok":true,
"tree":"6a75203c9cbb8c1208962f79aa8af1d7d8f3d1a9"}
head_reflog_before=['88a70edc957a0949c43f44d0fb8c1970fd7af02c']
head_reflog_after=['88a70edc957a0949c43f44d0fb8c1970fd7af02c']
branch_reflog=['65b46863afcdf166e53588add5ddade96366bed4',
 '88a70edc957a0949c43f44d0fb8c1970fd7af02c']
```

The final commit is recoverable only through the branch reflog, not the
worktree HEAD reflog expected from a normal commit.  This is an audit and
recovery regression in the very crash-safety path being introduced.

### Required remediation

Preserve the actual worktree HEAD reflog transition atomically with the
successful CAS publication (including linked-worktree `logs/HEAD` placement),
and add normal plus linked-worktree regressions comparing native commit and
claim-transaction reflog behavior.  Do not synthesize an unguarded post-hoc
write; it must remain inside the protected publication boundary.
