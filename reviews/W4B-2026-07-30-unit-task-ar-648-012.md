## P1 — `template_mirror_gate.py` ignores a missing side

`analyze()` builds `common = source.keys() & template.keys()` and evaluates
only that intersection.  It emits findings for a missing *directory* and for
an allowlisted exception that is no longer common, but it emits no finding for
a non-allowlisted eligible script that exists only in `scripts/` or only in
the packaged template.  Neither the gate nor its tests maintain the expected
84-path common inventory.

Independent temporary-fixture reproduction (outside every repository) created
only `scripts/source_only.py`, an empty valid contract, and an otherwise empty
template scripts directory.  Running the exact product gate with
`--check --json` returned exit `0`:

```json
{
  "eligible_common": 0,
  "identical": 0,
  "intentional": 0,
  "findings": []
}
```

This is a direct bypass of UNIT-012's required “missing side ... fail-closed”
property.  It also permits a previously portable common script to be deleted
from the template: it disappears from the intersection rather than becoming
`unlisted-drift`.  The current `84/81/3` census and the three digest pins are
accurate only for today's tree; they cannot enforce the promised future
surface.  W4a's claim that a missing side blocks is therefore incorrect.

Required repair: commit an explicit, exact expected-common inventory (or an
equivalent packaging manifest) for the 84 portable paths.  The gate must block
when any listed path is absent on either side, while continuing to permit the
known root-only/template-only populations outside that inventory.  It must
also block additions/removals that alter the expected common surface unless a
reviewed contract update accompanies them.  Add source-only and template-only
negative tests, including deletion of a formerly common unlisted script; do
not solve this with a wildcard exception or a count-only assertion.
