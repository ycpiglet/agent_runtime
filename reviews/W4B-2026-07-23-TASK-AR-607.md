## Failure-First Provenance

### Process-global subprocess leakage

Commit `af04a80a2cc45aa9d7aacad3cd85958d74a8ee7c` was exported to a
disposable directory and its new isolation test was run against the old module
loader:

```console
python -m pytest \
  tests/test_release_cadence_trigger.py::test_loaded_module_subprocess_patch_is_process_local -q
# 1 failed in 0.99s
```

The assertion observed global `subprocess.run` equal to the test sentinel,
proving that patching `module.subprocess.run` modified the shared imported
module. Commit `b9872cd5` gives the loaded module a private
`SimpleNamespace(run=subprocess.run)`, closing that leak.

### Process-global time leakage

Commit `133efabb6a7a6bf38117dac31863f1f30268dd5b` added the equivalent time
assertion after subprocess isolation. Its export failed independently:

```console
python -m pytest \
  tests/test_release_cadence_trigger.py::test_loaded_module_subprocess_patch_is_process_local -q
# 1 failed in 0.78s
```

The subprocess assertion passed, then `time.sleep` was observed as the test
sentinel instead of the original built-in. Commit `8ecfb10b` adds a private
time facade containing the real `sleep` and `time` callables. The two-step
history therefore isolates two distinct causal defects rather than weakening
one test until it passes.

The disposable exports and the 100-run repository were removed after their
probes.
