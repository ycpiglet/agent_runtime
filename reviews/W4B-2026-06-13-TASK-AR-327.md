# W4b Independent Verification — TASK-AR-327 (Channels View + Meeting/Seminar)

Independent verification of the Slack/Discord-style channels view + meeting/seminar
summon. NOTE: this is a re-verification after W4b caught and the worker fixed a
critical bug.

## Critical bug caught by W4b (now fixed) — RESOLVED
Original commit (3abff10): the channels submit handler called
`sendJson("/api/commands", parsed.command)` passing the full command object where
`payload` was expected, so the HTTP body was the INNER payload only with no
top-level `type` → submit_command rejected it (HTTP 400). All three channel
actions (/meeting, /seminar, plain directive) were dead — acceptance unmet.
Fix (4ec5be2): wrap as `sendJson("/api/commands", {type: parsed.command.type,
payload: parsed.command})`, matching every other /api/commands caller. Added 4
end-to-end tests posting the exact body through build_response → assert 202,
status=queued, mutation_boundary=proposal_only, proposal written, reviews/
untouched, plus a guard test for the old 400 form.
