## Blocking findings

### 1. Public inventory still exposes ignored and generated paths

`run_inventory()` continues to call `analyze()`, which in turn uses the old
filesystem `iter_repo_paths()` rather than `adoption_scan()`
([inventory.py](/home/keti-itp-01/ycpiglet/agent_runtime/.worktrees/TASK-AR-641/src/agent_runtime/inventory.py:375)).
An isolated Git fixture with `.gitignore`, `ignored/private.md`, and
`.next/cache/0.txt` reported both paths through the public inventory.

The live public command, `python -m agent_runtime.cli inventory`, likewise
leaks generated-like paths: Bean Wiki **10,387 / 11,140** and Allimbot
**2,360 / 2,926**. The new adoption-only filter is insufficient for the W0
inventory boundary.

### 2. Generated trees are expanded into one action per file

`build_adoption_plan()` appends a generated `skip` action for every member of
`scan.generated_paths`
([adoption.py](/home/keti-itp-01/ycpiglet/agent_runtime/.worktrees/TASK-AR-641/src/agent_runtime/adoption.py:116)).
This negates the brownfield scaling objective:

| Pilot | Generated count | Total actions | Generated actions |
| --- | ---: | ---: | ---: |
| Bean Wiki | 72,129 | 72,597 | 72,129 |
| Allimbot | 56,246 | 56,714 | 56,246 |

Generated trees must be represented by deterministic counts/root summaries,
not tens of thousands of machine actions. The JSON inventory also has no
`ignored_count` field, so the requested ignored-boundary contract is not
observable.

### 3. Ownership resolution breaks explicit generated and root-instruction seeds

`_ownership()` uses exact equality and returns `generated` for an explicit
`ownership.generated: [AGENTS.md]`, but planning a missing file emits
`add/generated` rather than the required generated `skip` producer/lifecycle
reason ([adoption.py](/home/keti-itp-01/ycpiglet/agent_runtime/.worktrees/TASK-AR-641/src/agent_runtime/adoption.py:64)).

It also seeds only `AGENTS.md` and `CLAUDE.md`. A pre-existing root `CURSOR.md`
is classified `managed` and becomes a conflict, despite the W0 requirement to
preserve root agent instruction seams. Include every recognized root
instruction file and apply explicit ownership consistently (including declared
directory scopes, if scopes are supported by the ownership table).

### 4. External source symlinks are invisible unless they collide with a template path

An external file symlink at `src-link` appeared in neither plan findings nor
actions; `doctor --pre-adoption --check` returned 0 with no unsafe-symlink
finding. Only template-target symlinks are inspected
([adoption.py](/home/keti-itp-01/ycpiglet/agent_runtime/.worktrees/TASK-AR-641/src/agent_runtime/adoption.py:92)).

The contract requires every symlink resolving outside the host root to be a
finding and never an action target. Scan source-visible symlinks directly,
avoid directory traversal, and propagate the finding into pre-adoption doctor.

### 5. Invalid configuration is presented as ready

For a v2 config with mapping-valued `project`, the plan contains a diagnostic
string but JSON returns `{"conflicts": 0, "ready": true}`. `doctor
--pre-adoption --json --check` also returns 0 and has only info findings.
Malformed config must be an explicit readiness blocker, not a non-blocking
fallback to core defaults.

### 6. The standalone doctor parser does not accept `--pre-adoption`

The public CLI route accepts the flag, but the standalone entry point
`python -m agent_runtime.doctor --pre-adoption --check` exits **2** with
`unrecognized arguments: --pre-adoption`. Its parser declaration was not
updated even though `doctor.main()` forwards `args.pre_adoption`
([doctor.py](/home/keti-itp-01/ycpiglet/agent_runtime/.worktrees/TASK-AR-641/src/agent_runtime/doctor.py:851)).
Add the flag to the standalone parser and cover both invocation routes.
