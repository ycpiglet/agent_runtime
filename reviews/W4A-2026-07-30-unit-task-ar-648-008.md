## Continuity Selection Contract

1. If `STATUS.md` or `agents/lead_engineer/STATUS.md` exists, the first
   canonical candidate is selected and must contain an existing handoff
   marker. Read failure or a missing marker blocks. The pointer is not used to
   bypass that result.
2. If both STATUS candidates are absent and active non-overlay claims exist,
   the canonical `agents/project/NEXT-SESSION-POINTER.yml` must validate.
3. Doctor additionally invokes this path with standby-pointer enforcement, so
   a fresh idle core installation must ship a usable non-placeholder pointer
   before the first claim.
4. Every active claim, including an explicit overlay, retains its existing
   handoff-file and log-file checks.
5. With no active worker claim, the normal parallel gate can remain idle;
   doctor is the component that requires the standby pointer.

The public report modes are `status+sidecars`, `pointer+sidecars`, and `idle`.
The CLI exposes the same decision through
`--continuity-only --require-standby-pointer --json`.

## Exact Pointer-to-Claim Matrix

Every active non-overlay claim must have exactly one current-agent entry with
all 22 fields:

```text
claim_id
agent_role
team_id
agent_instance_id
display_name
callsite_id
pane_id
task_id
unit_id
task_set_id
status
phase
progress_pct
step_index
step_total
status_text
worktree_path
branch
claim_path
handoff_path
log_path
last_heartbeat
```

`claim_path` is compared to the claim record's repository-relative path; the
other 21 fields are compared to the claim payload after scalar
normalization. `pointers.active_claims` and
`active_work.current_agents[*].claim_id` must each be exact, duplicate-free
sets for all active non-overlay claims. `resume.active_task` plus
`resume.active_task_set` must select an active claim, and
`resume.next_actions` must contain a concrete non-empty action.

Both pointer `updated_at` and claim `last_heartbeat` must be timezone-aware
ISO-8601 timestamps. The pointer timestamp cannot predate any active claim
heartbeat.
