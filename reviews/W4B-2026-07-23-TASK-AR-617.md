- VT `U+000B`
- FF `U+000C`
- FS `U+001C`
- GS `U+001D`
- RS `U+001E`

## 재작업 요구사항

1. `str.splitlines()`가 인식하는 모든 물리 줄 경계를 unsafe로 분류해야 한다: `\n`, `\r`, `\v`, `\f`, `\x1c`, `\x1d`, `\x1e`, `\x85`, `\u2028`, `\u2029` 및 CRLF.
2. marker JSON 문자열 내부에도 실제 splitline 문자가 남지 않아야 한다. `ensure_ascii=True` 또는 동등한 명시적 escaping으로 물리 한 줄을 보장해야 한다.
3. 각 경계에 대해 scalar와 block-list를 모두 검증하고 등록·검증·종료 lifecycle 회귀 테스트를 다시 실행해야 한다.
4. T3 범위대로 `strip_comment`와 기존 quoted/escaped/flow/plain-comment 의미는 유지해야 한다.

## 잔여 위험

- reserved marker는 인증된 envelope이 아니라 parser opt-in marker다. frontmatter 작성 권한 자체가 metadata 제어 권한이라는 현재 위협 모델에서는 권한 상승으로 보지 않았지만, marker collision 계약은 계속 회귀 테스트가 필요하다.
- parser는 의도적으로 완전한 YAML parser가 아니다. 따라서 지원하지 않는 문법을 일반화하지 않고 T3가 규정한 surface만 유지해야 한다.
- 전체 pytest는 timeout으로 미측정 상태다. 이 보고서는 focused scope 밖의 회귀 부재를 주장하지 않는다.
