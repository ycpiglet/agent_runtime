W4a found and repaired four issues before fixing the review head:

1. the closeout path originally had no integration proof that verification
   JSON, review refs, and compound refs stayed separate; direct `work close`
   fixtures now prove both the linked pass and unrelated-ref rejection paths;

   marked a missing legacy log as already seeded; the canonical fixture now
   records an empty seed set until a real first install occurs;
3. the sanitizer correctly rejected a test fixture shaped like a real secret;
   the fixture now exercises secret rejection without embedding a publishable
   secret pattern;
4. automatic closure inference initially accepted a record linked to any active
   claim. It now uses one exact current-worktree claim, accepts one unambiguous
   legacy active claim, and fails closed on multiple ambiguous claims unless
   `--work-id` is explicit.

  fail closed.
- Concurrent writers create distinct immutable files and rebuild one
  deterministic index.
- Claim targets strip the readiness-only `new:` marker before conflict and
  persistence checks.

  refuses malformed canonical stores without creating a claim.
- `work close` retains passed verification JSON as its own evidence class and
  validates review/compound refs against the unit, task, or declared defect
  signature.

  work before close.

  records; ambiguous multi-claim inference fails closed.
- `compound_log.md`, per-record data, and `INDEX.json` resolve respectively to
  `seed_once`, `host_owned`, and `generated`; sync/adoption/lock tests prove
  none is silently overwritten or permanently managed.
