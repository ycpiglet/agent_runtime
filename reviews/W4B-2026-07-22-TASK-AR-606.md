## Independent Platform-Boundary Exercise

The auditor loaded the real current `lock_merge_driver.py` and supplied a
controlled filesystem boundary to exercise mode semantics independently of
Windows chmod emulation:

```text
POSIX_IDEMPOTENT=PASS mode=0755 chmod_calls=1
WINDOWS_NOOP=PASS filesystem_touched=false
NONREGULAR_DIRECTORY=PASS chmod_calls=0
NONREGULAR_SYMLINK=PASS chmod_calls=0
MISSING_PATH=PASS chmod_calls=0
```

For a regular `0644` hook, `is_pre_commit_executable(..., posix=True)` first
returned false; repair returned true and produced `0755`; readiness then
returned true; a second repair returned false without another chmod. For the
Windows branch, the path constructor was configured to fail if called and was
never reached. Directory, symlink, and missing-path cases all remained
non-ready and unchanged. This directly verifies idempotency, the Windows no-op,
and the `lstat` regular-file guard used by both install and bootstrap flows.
