## Partial Failure Behavior

A second disposable host intentionally had an invalid claim JSON, no Git
repository, no `work.py`, and no `inflight_overlay.py`. The real CLI still
returned exit 0 and a structured W0 object with `status=ok`,
`source=fallback`, `worktrees=null`, `inflight: unavailable`, and these three
explicit notes:

- claim ignored due to `JSONDecodeError`;
- worktree scan unavailable because Git returned nonzero;
- inflight scan unavailable because the script was missing.

All files retained identical hashes. The fallback therefore degrades visibly
without converting partial read failures into state mutation or a blocking
session-start exit.

## Parity And Timeout Budget

The live and template `session_dashboard.py` files are byte-identical.
Independent instrumentation observed both fallback subprocess calls using the
configured five-second timeout. The declared worst-case serial budget is:

```text
2 * W0 fallback 5s + SCM 10s + update-notify 10s = 30s
```

Both root and template SessionStart hooks allocate 35 seconds, exceeding that
budget. The regenerated host lock independently passed its current check.
