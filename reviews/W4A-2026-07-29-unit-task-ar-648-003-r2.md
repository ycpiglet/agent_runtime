authorized claim commit could fail after `git add`, leave the claim staged,
and still pass `parallel_worktree_gate.py`. The gate now treats a claim as SCM

## Product Boundary

`parallel_worktree_gate.py` no longer uses
`git ls-files --others` as its persistence oracle. For every claim JSON
present in the host, it now requires both:

1. `git cat-file -e HEAD:<claim-path>` to prove the path exists in `HEAD`; and
2. `git diff --quiet HEAD -- <claim-path>` to prove the current record matches
   that persisted version.

The severity contract is unchanged except that it now covers staged and
modified records as well as untracked records:

| Claim persistence metadata | Current JSON versus `HEAD` | Result |
| --- | --- | --- |
| `scm_commit`, authorized | present and equal | pass |
| `scm_commit`, authorized | absent or different | block |
| `working_tree`, unauthorized | absent or different | watch with loss warning |
| missing or inconsistent | absent or different | block |
| spike-tagged | absent or different | watch |
