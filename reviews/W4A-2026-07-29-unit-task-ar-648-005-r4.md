## Final Transaction Contract

1. Remove repository-redirecting `GIT_*` inputs and resolve the real
   worktree-specific Git directory and common Git directory.
2. Stage only the requested claim artifacts in the real index for visible
   recovery while retaining every unrelated real-index entry.
3. Build a mode-`0600` private index from starting `HEAD`, add only the claim
   JSON, handoff, and log, record their exact mode/blob OIDs, and seal the
   complete tree.
4. Persist a child-only v2 marker binding root, owner PID, nonce, claim paths,
   starting `HEAD`, symbolic ref, private index, artifacts, and tree.
5. Run `pre-commit`, `prepare-commit-msg`, and `commit-msg` against the private
   index, then revalidate the tree, artifacts, record, branch, `HEAD`, and
   message.
6. Create the commit from the immutable tree, then open the actual symbolic
   `HEAD` regular file with POSIX `O_NOFOLLOW`. Retain its descriptor and seal
   its device, inode, link count, and exact `ref: <branch>` bytes.
7. Create a private mode-`0700` `reference-transaction` hook context using
   the exact Runtime Python interpreter.
8. Ask Git in the actual worktree context to execute
   `update-ref --create-reflog HEAD <new> <old>`.
9. In Git's `prepared` phase, while Git owns the actual worktree
   `HEAD.lock`, require the held file identity, original symbolic ref, old
   OID, and exactly the authorized `HEAD` plus branch transitions. Delegate
   the repository's configured reference hook, then repeat the checks.
10. Let Git atomically publish the branch ref, shared branch reflog, and the
    normal or linked-worktree-local `HEAD` reflog.
11. Reacquire the actual worktree `HEAD.lock` with `O_EXCL`. Under that lock,
    require the current `HEAD` path to be the still-open inode, then verify
    symbolic ref, commit OID, branch reflog, and actual `HEAD` reflog.
12. Run `post-commit` under the Runtime-owned lock, recheck identity and
    publication state, release only the owned lock, and clean all private
    transaction state.

A pre-existing external `HEAD.lock` fails closed and is never removed.
Configured reference-hook vetoes are honored. On Git 2.36 or newer, delegated
hooks run through `git hook run`; older POSIX Git runs the exact configured
executable path. A recursion alias to the private hook is rejected.

## Partial-Publication Contract

Once Git's ref transaction succeeds, Runtime never describes a later
verification failure as an ordinary rollback-safe failure:

- lock contention or an identity/ref/reflog mismatch returns `ok=false`,
  `committed=true`, and `publication_state=published_unverified`;
- `post-commit` is skipped when verification before it fails;
- the claim CLI exits non-zero;
- the dispatcher emits `created_published_unverified`, exits non-zero, and
  explicitly forbids retry;
- cleanup removes only Runtime-owned private paths and locks; it does not
  attempt a compensating ref rollback.

The registered dispatcher integration proves a committed reference hook can
perform the `A -> B -> A` round trip only by producing exactly one published
commit and a terminal non-success. It is not retried or reported as created
success.

## Portability and Threat Boundary

The identity seal is supported only on POSIX platforms that provide
`O_NOFOLLOW`. Unsupported platforms fail before any ref publication on the
explicit SCM path; default working-tree claim persistence remains available
cross-platform.

The seal covers cooperative concurrent Git operations that use normal
lockfile replacement. Repository hooks run with the user's authority and are
trusted code: they may observe or veto the transaction but must not mutate
Git administrative state. An arbitrary same-authority process that directly
rewrites `.git/HEAD` in place instead of using Git's lockfile protocol is
outside this concurrency boundary.
