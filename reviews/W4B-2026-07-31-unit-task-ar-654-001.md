## P1 — Empty/null accepted-watch reviewer values approve repeated-failure closure

The Markdown watch parser stores any non-empty inline value as an untyped
string (`src/agent_runtime/knowledge_records.py:173-214`). The reviewer check
then treats any non-empty normalized string as an identity
(`src/agent_runtime/knowledge_records.py:255-261`). Consequently these normal
YAML representations of “no reviewer” are accepted as reviewer identities:

```yaml
status: accepted
decision: accepted_watch
reviewed_by: []
work_id: UNIT-TASK-AR-999-001
```

and:

```yaml
reviewed_by: null
```

An isolated disposable-repository reproduction linked such a watch from a
canonical current-unit Compound carrying a valid defect signature. Results:

- `closure_gate.assess(..., work_id=UNIT-TASK-AR-999-001)` returned
  `decision=approve`,
  `reason=repeated-failure-compound-present`,
  `repeat_failure.satisfied=true`, and zero findings.
- The actual CLI
  `python scripts/work.py --root <temp> close UNIT-TASK-AR-999-001
  --actual-hours 1 --actual-tokens 1 --json`
  returned `0` and `status=closed`.

Both consumers trust `validate_prevention_destinations()` without further
reviewer validation (`scripts/work.py:2538-2547`;
`scripts/closure_gate.py:364-375`), so this is semantic parity in the wrong
direction: both mandatory gates accept an unreviewed watch.

The same adversarial matrix found a second manifestation of the overly broad
accepted-watch contract: a watch with no `decision` field is accepted when it
uses only `disposition: accepted_watch` or
`prevention_status: accepted_watch`, because all three fields are treated as
equivalent (`src/agent_runtime/knowledge_records.py:54-58,244-249`). The
accepted T3 contract and shipped skill explicitly require
`decision: accepted_watch`.

Required repair:

1. Preserve or strictly validate frontmatter value types so YAML nulls,
   booleans, empty inline containers, and placeholder scalar spellings cannot
   become reviewer identities.
2. Require the explicit `decision` field named by the contract, or formally
   amend the contract and skill before accepting aliases.
3. Add end-to-end negatives for `reviewed_by: []`, `reviewed_by: null`,
   `reviewed_by: false`, and alias-only decisions through both `work.py close`
   and the work-linked Stop gate.
