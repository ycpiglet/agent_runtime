## Code and Test Review

- `_task_record_candidates` scans the repository's flat task directory in a
  deterministic case-insensitive filename order.
- Filename matching is either exact stem equality or a `TASK-ID-` prefix. The
  required hyphen boundary prevents `TASK-2310` from matching `TASK-231`.
- Metadata matching uses exact string equality against `work_id`, `id`,
  `display_id`, and `task_id`; it does not use substring matching.
- Each file path is appended once even when both its filename and metadata
  match, so one healthy canonical record cannot create self-ambiguity.
- Zero candidates preserve `pointer-task-missing`. More than one candidate
  produces `pointer-task-ambiguous` with every deterministic relative path;
  no candidate is selected silently.
- The same resolver and pointer logic are mirrored in the generated-host
  template, and the host lock changes only for the mirrored script digest and
  aggregate template digest.
