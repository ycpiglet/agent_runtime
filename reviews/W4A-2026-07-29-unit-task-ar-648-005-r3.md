## Final Transaction Contract

1. Sanitize repository-local `GIT_*` redirectors and resolve the real
   worktree-specific Git directory plus common Git directory.
2. Stage only requested claim artifacts in the real index for visible
   recovery while preserving every unrelated real-index entry.
3. Create a mode-`0600` private index from starting `HEAD`, add only the claim
   JSON, handoff, and log, record exact mode/blob OIDs, and seal `write-tree`.
4. Persist a child-only v2 marker binding root, owner PID, nonce, claim paths,
   starting `HEAD`, symbolic ref, private index, artifacts, and sealed tree.
5. Run `pre-commit`, `prepare-commit-msg`, and `commit-msg` against that
   private index, then revalidate the entire tree, every working artifact
   blob, record bytes, branch, `HEAD`, and message.
6. Create the commit from the immutable tree before entering the short
   publication critical section.
7. Create a private mode-`0700` Git administrative context with detached
   `HEAD` at the starting object and absolute `commondir` at the repository's
   real common Git directory.
8. Exclusively create the actual worktree `HEAD.lock`, repeat final validation
   under that lock, and use Git's
   `update-ref <original-ref> <new> <old>` through the private context.
9. Verify the real worktree still has the original symbolic ref and that its
   `HEAD` resolves to the sealed commit.
10. Run `post-commit` after publication while the owned `HEAD.lock` remains
    held. A hook failure is a warning because publication already occurred;
    the hook cannot perform a compliant symbolic branch switch.
11. Release only the lock whose device/inode token matches this transaction
    and remove the marker, private index, message, and detached context on
    every exit.

The detached context is used only for the final ref CAS. Hook discovery,
commit hooks, signing configuration, and `commit-tree` remain in the actual
worktree context. A pre-existing external `HEAD.lock` fails closed and is not
removed.
