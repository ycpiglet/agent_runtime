# Meeting: RSI Planning Loop And Agent Departments

## Context

- Date: 2026-06-10
- Scope: `agent_runtime` planning loop, self-improvement, task generation, and
  agent department model.
- Source: user requested registration of the proposed B-C path, recording of the
  conversation, and explicit inclusion of trace, grader, eval, release/version
  consistency, history, review, compound, retro, and RSI stability ideas.

## User Intent

- Add an autonomous system that checks task progress, project content, and the
  current plan after cycles or meaningful work completion.
- Let that system create new tasks, revise plans, update planning documents, and
  preserve continuity without requiring a second manual Codex pane.
- Extend the existing doc-steward idea with roles for version/release
  consistency and historical review/compound/retro synthesis.
- Keep recursive self-improvement productive, systematic, structural, stable,
  and non-divergent.
- Build a larger multi-agent organization with diverse perspectives, including
  critique, advocacy, agreement, friction, exploration, and stabilization.
- Research comparable theories and examples before locking the plan.

## Decision Notes

- Adopt B-C as the roadmap:
  - B: proposal-first planning loop with scan, proposal outbox, review, and
    approved apply.
  - C: long-term bounded auto-planning after evidence, gates, and rollback
    paths are proven.
- Register `TASK-AR-234` through `TASK-AR-245` as the implementation chain.
- Treat trace/eval/grader outputs as evidence that can create proposals and
  acceptance criteria, not just quality dashboards.
- Add new departments for planning, release integrity, RSI retro/compound,
  evaluation evidence, risk/stability, and viewpoint diversity.
