## W4b Finding 1 — Strict Typed Unit-Frontmatter Grammar

The former scalar reader applied:

```text
value.strip().strip("\"'")
```

That normalized malformed quote syntax into trusted values. The replacement
parser validates the complete supported frontmatter subset before any
security-decision field is used.

Supported values are deliberately small:

- exact plain scalars without unsupported YAML indicators;
- well-formed JSON double-quoted strings;
- well-formed YAML single-quoted strings with doubled-quote escaping;
- exact lowercase boolean literals `true` and `false`;
- bounded block lists using the same scalar grammar; and
- simple inline lists whose individual items pass that grammar.

It rejects:

- unterminated or trailing unmatched single and double quotes;
- YAML tags, anchors, aliases, block scalar prefixes, and container syntax;
- inline-comment syntax in decision values;
- empty or malformed list items;
- tabs, NUL bytes, control characters, unsupported indentation, and malformed
  keys;
- duplicate frontmatter fields; and
- unsupported nested structure.

Requirement matching remains exact. In particular:

```text
security_sensitive: true    -> boolean true
security_sensitive: "true"  -> string "true", does not satisfy requirement
approval_required: 'true'   -> string "true", does not satisfy requirement
risk_tier: " high "         -> string with spaces, not normalized to high
```

The exact sixth-W4b dispatcher input is now refused:

```text
target: .env.production
risk_tier: "high
security_sensitive: "true
approval_required: "true
escalation_triggers: [security]
section: ## Security Controls

returncode=1
stderr includes policy_error
persisted_claims=0
```

Adjacent regressions cover single-quote truncation, `!high`, `&high`, `*high`,
`|`, `|+`, `>2`, `{value: high}`, unmatched closing quotes, and inline
comments. Positive regressions retain valid quoted risk text and inline
trigger lists.

## W4b Finding 2 — Bounded Stable Canonical-Unit Snapshot

The unit decision source now uses one captured byte snapshot with a hard
`256 KiB` limit. Before trusting it, Runtime:

1. validates the repository root and every relative-path component with
   `lstat()`;
2. rejects symlinked components, non-directory parents, and a non-regular
   final node;
3. rejects a final node with no read bit or a size outside the managed bound;
4. opens with `O_NOFOLLOW`, `O_CLOEXEC`, and `O_NONBLOCK` where available;
5. compares descriptor signatures before and after the bounded read;
6. compares device, inode, mode, size, modification time, and change time
   against the pre-open path snapshot;
7. rechecks every path component after the read; and
8. decodes only the already captured bytes as UTF-8.

The parser, identity check, target registration, required metadata check, and
required-section check all consume that one captured string. Tests cover an
oversized unit, a mutation during the snapshot, a symlinked unit, a
non-canonical substitute document, mismatched identities, and duplicate
frontmatter fields.

Required Markdown headings are collected only from rendered-level text.
Headings inside backtick/tilde fences and HTML comments do not satisfy
`Security Controls`, `Rollback`, or `External Effect Boundary`.

## Verification-Harness Isolation Finding

outer command used a relative `PYTHONPATH=src`; the dispatcher intentionally

host and then fall back to an editable install from a different Git
worktree, where the new module was absent.

```text

```

The test helper now prepends the resolved current-worktree `src` path to the
nested environment. This does not turn an unavailable production gate into a
success: the dispatcher still refuses closed when its installed module is
unavailable. It only makes the fixture exercise the product package belonging
to the checkout being verified.

The failed evidence is retained rather than overwritten. The corrected
dispatcher file passes all 46 tests under the original relative outer
environment.
