## Blocking Findings

### 1. Caller-controlled credential-, provider-, and URL-shaped values cross the event boundary

`_SAFE_IDENTIFIER` allows `:`, `/`, and arbitrary token-shaped strings, and
`_validate_event()` applies that same generic check to every string field
(`src/agent_runtime/allimbot.py:27`, `src/agent_runtime/allimbot.py:136-180`).
It therefore does not enforce the documented semantic boundary that
credentials, endpoint URLs, provider destinations, and arbitrary caller text
are outside the producer API.

An isolated fake-emitter probe, with no optional package or network, accepted
and forwarded all of these synthetic values:

```text
event_type=task.state.changed
task_id=sk-proj-SYNTHETIC-CREDENTIAL-123
from_state=provider-slack
to_state=https://events.invalid/destination
result.status=spooled
captured summary=
  Task sk-proj-SYNTHETIC-CREDENTIAL-123: provider-slack ->
  https://events.invalid/destination (owner=runtime)
captured data contains the same values
```

This directly contradicts the task acceptance criterion that caller-provided
credential text and provider destinations cannot be forwarded. The existing
test rejects a newline-bearing value, but does not cover display-safe secrets,
URLs, or provider labels.

Required rework:

1. replace the one-size-fits-all identifier policy with field-specific
   canonical patterns/allowlists;
2. remove URI syntax from accepted structured identifiers and reject known
   credential-shaped values before optional import;
3. constrain state, result, attention-kind, and owner-role values to managed
   vocabularies or trusted Runtime-derived values;
4. add failure-first tests proving synthetic token, URL, provider, prompt, and
   exception-shaped values never reach emitter construction or `emit()`.

### 2. Security-service claims can bypass both pre-claim and active-claim enforcement

The dispatcher returns “not refused” when the security gate is installed but
`unit_spec` is empty (`scripts/task_claim_dispatcher.py:694-703`). The active
claim recheck likewise skips an active risky claim with no unit spec
(`src/agent_runtime/security_service.py:453-461`).

Independent probe:

```text
gate_present=true
unit_spec=""
target_files=[".env.production"]
preclaim_refused=false
active_risky_claims_reported=0
```

A second bypass exists when a unit spec is present. Explicit
`--target-file` values replace, rather than augment or validate, the unit's
registered `target_files` (`scripts/task_claim_dispatcher.py:373-377`), and
`analyze_unit()` then analyzes only that override
(`src/agent_runtime/security_service.py:397-420`).

Independent probe:

```text
registered unit target=.env.production, low-risk metadata -> block
same unit with explicit target override README.md -> pass
override classifications=0
```

Required rework:

1. in a selected security-service profile, refuse a claim with target files
   but no valid registered unit spec;
2. analyze the union of registered unit targets and the claim snapshot, or
   fail closed when an explicit footprint narrows/diverges from the unit;
3. make active-claim validation report/block missing or malformed unit
   references and invalid target snapshots instead of skipping them;
4. add dispatcher and active-claim regression tests for empty unit specs,
   narrowed overrides, empty snapshots, and malformed snapshots.

### 3. Invalid host configuration silently disables `host.risk_paths`

`_host_risk_paths()` catches every exception from `load_config()` and returns
an empty tuple (`src/agent_runtime/security_service.py:217-221`). That converts
a malformed security overlay into a passing gate and silently removes the
host-specific production external-effect boundary.

Independent temporary-host probe used a syntactically invalid v2
`host.risk_paths` shape and a low-risk unit targeting
`services/prod/client.py`:

```text
status=pass
classifications=0
findings=0
```

Required rework:

1. propagate configuration failures as bounded `SecurityPolicyError` so the
   security gate blocks;
2. distinguish a valid empty `risk_paths` list from an unreadable/malformed
   host configuration;
3. add failure-first tests for missing, malformed, unsafe, and valid
   `host.risk_paths` configurations at both unit and claim-dispatch seams.
