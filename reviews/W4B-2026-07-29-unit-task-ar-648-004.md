# TASK-AR-648 UNIT-004 Independent W4b

## Bottom Line

**REQUEST_CHANGES — P0.** The explicit claim-only commit exception does not
bind the approved claim blob to the final Git tree.  A claim can pass the real
pre-commit gate, be re-staged with different content before `git commit` writes
its tree, and then be committed successfully.  This violates UNIT-004's
requirement that the exception applies only to the exact staged claim in the
live child transaction.

No claim was released.  No Bean or other consumer worktree was created or
changed.

## P0 — Gate/Commit TOCTOU Permits a Different Claim Blob

`claim_guard._start_commit_transaction()` records only claim **paths**, root,
PID, nonce, and starting `HEAD`.  It does not record the claim's index blob.
`parallel_worktree_gate._claim_matches_index()` compares index and working-tree
blobs only when its pre-commit invocation runs.  Git hooks may stage files
after that invocation and before `git commit` writes the commit tree.

### Independent reproduction

In a disposable linked Git worktree, I installed an executable pre-commit hook
which first ran the unmodified Runtime gate, then (only after its successful
return) read the child transaction marker, changed that listed JSON's
`status_text` to `modified after successful gate validation`, and ran `git add`
for that same path.  I invoked the real dispatcher:

```text
python .../scripts/task_claim_dispatcher.py create \
  --task-id TASK-AR-648-RACE --worktree-path . --agent-role lead-engineer \
  --now 2026-07-29T20:30:00+09:00 --suffix race \
  --commit-claim-artifacts --json
```

Observed result:

```text
commit=ee631907d17aeeadc8ac0ff90e04ca30e0b8c46c
committed_status_text=modified after successful gate validation
transaction_marker_count=0
post_commit_gate_rc=0
parallel-worktree-gate: pass
block=0
watch=0
```

Thus the gate accepted one blob but `HEAD` contains a later, different blob
under the same authorized path.  This is also a practical race with any
concurrent index writer during the hook window; the proof uses a hook solely to
make the timing deterministic.  The existing hook itself stages generated
artifacts after owner-governance, so the index is intentionally mutable during
this phase.

### Required remediation

Treat the transaction as a final-content transaction, not a path transaction:
bind every authorized claim JSON's object ID to the marker and ensure the
validation is the final operation before Git constructs the tree, with no later
index mutation permitted.  Add a real-hook regression that changes and stages
the authorized JSON after the gate; it must abort and leave ordinary
post-failure `authorized-commit-not-persisted` blocking intact.  A path-only
marker plus a one-time index/working-tree comparison is insufficient.
