## P1-1 — Packaged ISO-second freshness failure is reproducible

The product root executable hashes to
`3a7589270b576a97f90e3121891ad08f510f6ed4bf352438bf0754a90143c22e` and
masks a `generated_at` value with either a date or an ISO second/time-zone.
The exact packaged template, which is byte-identical to Bean's installed
executable, hashes to
`fe840225c2fe9e6a11769d370f3f9920f532bd95fcc20a59a75449ff226652e6` and
masks only a date.

Read-only reproduction against the terminal Bean root produced exactly one
remaining masked diff:

```diff
-generated_at: 2026-07-30T03:23:06+09:00
+generated_at: 2026-07-30T03:29:40+09:00
```

Accordingly, the installed command returned exit 1 with only
`BACKLOG-BOARD.md: stale:content-mismatch`.  The same frozen Bean root and
complete taskset, evaluated with the exact root executable, returned
`findings=0`.  This control eliminates claims, task state, and board semantic
content as causes: wall-clock time alone changes the result.

The root test file currently passes (`10 passed`) but its freshness test
replaces `generated_at` with the date-only value `2026-06-01`; it neither
executes the packaged script nor covers a real ISO timestamp.  Therefore the
test result does not release this shipped regression.

Required repair: synchronize the root semantics to every executable packaged
mirror, add a root/template parity guard, and add a delayed-render or injected
ISO-second fixture that proves both copies accept identical task/claim state.
Audit all executable mirrors rather than applying an unguarded one-file copy.
