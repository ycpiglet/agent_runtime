standard-library-only dashboard/ntfy routing while intentionally strengthens
the upstream sample by capping caller-provided timeouts and making the CLI

## Blocking findings and residual risk

Blocking findings: **none**.

Residual risks are bounded and non-blocking:

- Enabling both routes while the dashboard is unavailable can add up to six
  seconds total because each of the two attempts has its own three-second cap.
- `urllib`'s timeout bounds socket operations; platform DNS resolver latency
  is not always a strict wall-clock guarantee. This is a standard-library
  limitation, while the code still passes `3.0` to every request.
- Stop notification is intentionally configuration-opt-in rather than a
  separate per-hook flag. A configured host receives the static Stop message;
  an unconfigured host remains fully silent.
- CI behavior was verified statically and through the same mocked client; no
  Actions secret was created and no workflow was dispatched.

The verifier changed no implementation, task, claim, board, index, registry,
or release file. This W4b report is the only verifier-authored artifact.
