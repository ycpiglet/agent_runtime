## Cleanup Receipt and Authority Boundary

`--write-projection` and `--record-cleanup` are mutually exclusive explicit
operations:

1. `--write-projection` atomically refreshes only the generated view.
2. Canonical cleanup occurs separately under a bounded Lead Engineer/Doc
   Steward task; Runtime never performs that edit automatically.
3. `--record-cleanup --authorization-ref <record>` records the result only
   after those edits already exist.

The receipt schema is `agent-runtime-scribe-cleanup-receipt/v1`. It binds:

- before and after source paths, SHA-256 digests, and hot counts;
- resulting hot count;
- active-work digest;
- cleanup-plan digest;
- repository-relative authorization reference;
- an optional owner-decision reference; and
- its own deterministic receipt digest.

An ordinary existing file such as `README.md` is not valid authorization.
Authorization must resolve, without symlink escape, to a canonical TASK or
UNIT-TASK record. A no-reduction outcome fails unless a repository decision
record explicitly authorizes no-touch; with that decision, the overdue source
debt remains visible even though closure is unblocked.

Receipts and projections contain no raw prompt bodies, transcript bodies,
secrets, private keys, or absolute host paths.
