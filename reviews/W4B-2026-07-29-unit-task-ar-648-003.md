# TASK-AR-648 UNIT-003 독립 W4b 재검증

## Bottom Line

**REQUEST_CHANGES — 38/100.**

제품 SHA `31b1a146a5c134358ee2ecd3e36c3a61ee07d13a`의 명시적
`scm_commit` 실패 경로가 release-blocking P0이다. `git add` 후 commit
hook/commit이 실패하면 claim JSON은 staged-only 상태로 남을 수 있는데,
parallel worktree gate는 untracked 파일만 검사하여 통과시킨다. 따라서
`scm_commit_authorized: true`인데 HEAD에 영속되지 않은 claim이 block되지
않는다.

## Action

`scripts/parallel_worktree_gate.py`가 claim JSON의 Git 상태를
untracked뿐 아니라 staged-but-uncommitted까지 판별하도록 수정한다.
`persistence.mode == "scm_commit"` 및
`scm_commit_authorized is True`인 active claim은 claim JSON이 `HEAD`에
존재하지 않으면 반드시 block해야 한다. 실제 commit-hook 실패 후 staged
claim을 재현하는 회귀 테스트를 추가한다.

## Risk

현재 gate의 `_untracked_claim_findings()`는 `git ls-files --others`
(`scripts/parallel_worktree_gate.py:567-621`)만 사용한다. 명시 commit
경로는 그보다 먼저 `git add`를 수행하므로 (`scripts/claim_guard.py:63-65`),
commit 실패 시 파일은 index에는 있으나 HEAD에는 없다. 이 상태에서 gate가
`parallel-worktree-gate: pass`를 내므로, 명시 SCM 영속 실패가 working-tree
watch나 무결점 상태로 잘못 보일 수 있다.

독립 재현: 임시 Git 저장소에서 유효한 active claim에
`{"mode":"scm_commit","scm_commit_authorized":true}`를 기록하고 claim
JSON만 `git add`한 뒤 gate를 실행했다. 결과는 `gate_rc=0`,
`findings=0`, `block=0`, 반면 `git status --porcelain`은
`A  agents/runtime/task_claims/CLAIM-STAGED.json`이었다.

## Decision

W4a JSON의 정식 7개 명령(131, 185, Bean validator, asset usage, owner
governance, sanitizer, full suite 2598 passed/3 skipped)과 W4a report의
제품 SHA는 서로 일치한다. 원본 red fixture 및 attempt-1 report 해시도
각각 `a8ad2dfb7f8b1e81c6606d4a51157270ca7fcfe24e0bd3750281d08a163a7a48`,
`e035fa71b0a826d4a4e6d9c6f55ea5bdfe08da540017d24cf28016c73ba459cb`,
`1418a0253cbd0e7684656ce13882ba27f31427321a5f6d6a79410c2ebca96a74`로
불변이었다. 그러나 위 P0 하나로 W4b 승인은 불가하다.

독립 확인에서 다음은 통과했다.

- absent/empty/false/malformed/case/whitespace 환경값은 HEAD를 바꾸지
  않았고, true 환경값 및 CLI opt-in만 claim commit을 만들었다.
- CLI opt-in commit에는 claim JSON/handoff/log 세 파일만 포함되었으며,
  사전 staged 파일과 untracked 파일은 남았다.
- `python -S`, `PYTHONNOUSERSITE=1`, 삭제된 `PYTHONPATH` 조건에서
  portable Scribe projection과 state-sync gate가 통과했다.
- 로컬 portable `agent_runtime.config`가 우선되고, 별도 full-package의
  `agent_runtime.cli`가 `extend_path`로 해석되는 namespace 재현이 통과했다.
- canonical/root/template portable state module 및 changed dispatcher/gate
  source-template parity가 일치했고, profile matrix는 core/web `246`,
  security/full `251`이었다.
