# Read-Surface Contract (TASK-AR-537)

The work store keeps markdown/JSON records as the **source of truth**. To stay
fast as the store grows toward thousands of files, agents and tools read the
**generated manifests** below instead of globbing hundreds of records.

## Canonical read surface (read these, not raw globs)

| Manifest | Generated by | Covers |
| --- | --- | --- |
| `BACKLOG-BOARD.md` | `scripts/backlog_board.py` | active work (Triage / Action / Rollups lanes) |
| `ARCHIVE-INDEX.md` | `scripts/backlog_board.py` | completed task files (id + lifecycle) |
| `agents/project/work-items/WORK-ITEM-CLASSIFICATION.json` | `scripts/work_item_classifier.py` | hierarchy ordinals (initiative/taskset/task/unit) |
| `agents/project/work-items/TASKSET-DEFINITIONS.json` | hand + UI sync | taskset registry |
| `agents/project/work-items/HOST-FEEDBACK-QUEUE.json` | `scripts/host_feedback_intake.py` | host feedback intake/triage |
| `reviews/INDEX.md` | `scripts/evidence_index_generator.py` | review/evidence records |

`python scripts/work_index.py --check` verifies these exist and reports corpus
size + whether a derived full-text index is warranted yet.

## Performance config (apply once per checkout)

Markdown/ripgrep are fine to tens of thousands of files; `git status` scales with
file COUNT. Apply (local, not committed):

```
git config feature.manyFiles true     # bundles untracked-cache + fsmonitor + index-v4
git config core.untrackedCache true
git config core.fsmonitor true
```

Editors bite earliest (VS Code default 8,192 inotify watchers) — `.vscode/settings.json`
sets `files.watcherExclude` for `.git`, `.venv`, `.worktrees`, caches.

## Derived index (DEFERRED until ~10k files)

When the corpus passes ~10,000 markdown files OR cross-corpus full-text query is
needed, add a derived **SQLite/FTS5** index:

- Rebuilt from the markdown via **mtime + content hash** (incremental; only changed
  files re-indexed).
- A **disposable cache**, never the source of truth — deletable and fully
  reconstructable from the records.
- Schema: one row per record (path, id, kind, status, signal, title, body-fts).

Until then, the manifest-first surface above is sufficient (`work_index.py`
reports when the threshold is crossed). This avoids premature infrastructure
(research: shard/index before ~5-10k, not before).
