# Vision

## Problem

멀티 프로젝트에서 Agent Runtime을 재활용할 때, 프로젝트별 컨텍스트 차이가 정의 충돌과 누락으로 이어지는 문제.

## Vision

- 프로젝트 고유 맥락을 `agents/project` 오버레이에 표준화.
- 공통 런타임은 동일 유지.
- 소스 정합/쿼리 정제/검증 루프를 통해 정확도를 게이트로 관리.

## Scope

- 현재 MVP는:
  - 프로젝트 오버레이 계약 정비 (`TASK-AR-211`)
  - 이식 감사 분류 정리 (`TASK-AR-209`, `TASK-AR-212`)
  - release gate 연결 강화 (`TASK-AR-204`, `TASK-AR-210`)
- 제외:
  - 제품별 스킬 로직 변경
  - 도메인 특화 모델 교체 정책(별도 TASK로 처리)

## Success metric

- 다중 프로젝트 투입 시 공용 런타임 수정 없이도 요구 컨텍스트가 일치.
- 오버레이 누락 질의에서 경고+보완 질문이 항상 발생.
- `TASK-AR-205` 오프라인 점수 0.90 미만은 게이트 보류.
